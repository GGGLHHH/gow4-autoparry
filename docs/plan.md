## 要解决什么

现在开关功能、调提前量、注入 / 卸载都要敲命令或手改 ini。做一个常见修改器那种形式的程序：
双击启动，`Insert` 在游戏上方弹出菜单，自己开关、自己调、`F12` 一键全关。

## 目标 / 不做

- **做**：一个 `gow4_trainer.exe`——找游戏、核对版本、注入 / 卸载两个 DLL；菜单四页（总览 / 战斗 / 透视 / 设置）；
  `F12` 总开关；成品是单个 exe（两个 DLL 编在里面）。
- **不做**：不把菜单画进游戏画面；不改战斗判定逻辑（v6.23 还没实战验证，一次只动一个变量）；
  不做日志查看器（设置页只放「打开日志」按钮）。
- **做坏了的样子**：菜单关着时还拖慢游戏；点一下开关要等好几秒才生效；修改器一崩把游戏带崩。

## 方案取舍

| 方案 | 结论 |
| --- | --- |
| 外部覆盖层（独立进程，透明置顶窗口 + 定制主题的 Dear ImGui） | **选这个**。和常见修改器一样的用法；菜单出错不影响游戏；覆盖层 / 主题 / 开关控件 / 注入 / 内嵌 DLL 都有现成的写法 |
| 菜单画进游戏画面（由注入的 DLL 画） | 不切焦点，但要在游戏窗口里截鼠标键盘、自己管光标，菜单崩 = 游戏崩，改一次菜单就得重新注入 |
| 普通桌面窗口 | 最简单，但每次调都要切出游戏 |

## 怎么做

```
gow4_trainer.exe ──写 ini + 置位「重读」事件──▶ gow4_autoparry.dll / gow4_esp.dll（游戏进程里）
        │                                              │
        └──────────◀── 共享内存里的状态（阶段 5，还没做）──────┘
```

- **配置**：功能设置的唯一来源是两个 DLL 的 ini（DLL 同目录的 `gow4_autoparry.ini` / `gow4_esp.ini`，DLL 只认自己旁边那份）。
  修改器读它们、只把改过的键逐项写回（`WritePrivateProfileString`，注释和别的键不动）；文件被手改了（修改时间变）就重读，界面跟着变。
  修改器自己的设置（按键、是否自动注入等）放同目录的 `gow4_trainer.ini`。
- **生效速度**：DLL 自己每 1 s（弹反）/ 2 s（透视）重读一次 ini。v6.24 起两个 DLL 各建一个命名事件
  `Local\gow4_autoparry_reload` / `Local\gow4_esp_reload`，修改器写完 ini 就置位，DLL 立刻重读。
- **总开关**：两个 ini 各有 `master=1/0`。弹反 DLL 里 `master=0` 时弹反 / 闪避 / 预判 / 预读 / 飞行物 / QTE 自动完成全部按关处理；
  透视 DLL 里整帧不画。各项自己的值不动，再按一次 F12 就恢复原样。
- **透视**：`gow4_esp.ini` 加 `enabled=1/0`（透视自己的开关）和 `show_<类别>=1/0`（15 类）。关着时渲染钩子直接返回，一帧都不画。
- **DLL 放哪**：开发版用 exe 同目录的 DLL（`build\Release`，和命令行 `gow4_inject.exe` 用的是同一份）；
  成品把两个 DLL 编进 exe，启动时释放到 `%LOCALAPPDATA%\gow4_trainer\<名字>_<内容哈希>.dll`，三个 ini 也放那儿。
- **注入**：「已注入」靠 DLL 自己建的卸载事件判断；注入前读游戏主模块里的 16 字节特征核对版本（只读），对不上就不注入并提示。
  游戏里那份 DLL 如果是从别的文件夹加载的（比如命令行从 `build\Release` 注入的，而开着的是成品修改器），总览页会提示
  「这里的设置对它不起作用」，要先卸载再从修改器注入。

### 我定的

- 菜单关着时**覆盖层窗口直接隐藏**：透视是 DLL 画在游戏画面里的，不需要覆盖层常驻；置顶透明窗口盖在游戏上会让系统多做一层合成。
  按 F12 时覆盖层只出现约 1.5 秒，在左上角显示「辅助已暂停 / 已恢复」。
- **启动要有反馈**：菜单默认收着、覆盖层藏着，双击后什么都看不到会像没启动。所以启动时游戏还没开 → 直接亮出菜单；
  游戏已经开着 → 左上角提示「已启动（Insert 开菜单）」；自动注入完再提示「辅助已注入」，失败就用红字写原因。
- **快捷键只在游戏或菜单在前台时认**：在浏览器里按 F12、在编辑器里按 End 不会误触。游戏没开时 `Insert` 在哪都认（先开菜单调设置）。
- **自动注入**：游戏进程起来满 15 秒、窗口有了、版本对得上才注入，每个游戏进程每个 DLL 只自动注入一次；
  只要在这个进程里见过它装着（包括别人注入的），之后被卸载了就不会再自动装回去——开发期命令行热替换 DLL 时不会被它抢文件。
- 退出修改器（`End` 或菜单里「退出」）时，卸载**它自己注入的** DLL；别处注入的不碰。设置页可关。
- 默认按键：`Insert` 菜单、`F12` 总开关、`End` 退出，都能改。注意别的修改器也常用这一组默认键，两个同时开着时一个键会触发两边。
- 菜单开着时切到别的程序，菜单自动收起。
- 编译 DLL 时不再覆盖输出目录里已有的 ini（`cmake/copy_if_missing.cmake`）：那里的 ini 是你 / 修改器改过的。

## 实现结构

```
src/common/shared.h            DLL 和修改器共用：游戏版本特征、事件名、ini 文件名 / 节名、透视 15 类的键名 + 中文名 + 颜色
src/trainer/main.cpp           入口：命令行（--shot / --check）、主循环、快捷键、提示条、单实例
src/trainer/overlay.{h,cpp}    覆盖层窗口 + 主题；另加离屏出图
src/trainer/widgets.{h,cpp}    ToggleSwitch / SliderRow / SegmentedRow / KeyBinder / StatusDot …
src/trainer/hotkeys.h          KeyEdge（全局快捷键边沿检测）
src/trainer/settings.{h,cpp}   Settings 结构 + SettingsStore（三个 ini 的读、逐项写、外部改动检测、置位重读事件）
src/trainer/menu.{h,cpp}       菜单窗口、标签页、提示条；MenuContext 把各页要的东西带进去
src/trainer/pages.cpp          四页的画法
src/trainer/game.{h,cpp}       找 GoW.exe、取窗口、版本核对、查某个模块是从哪加载的（全是只读）
src/trainer/injector.{h,cpp}   注入（远程线程 LoadLibraryW）、查事件、置位事件
src/trainer/dll_files.{h,cpp}  两个 DLL 文件和 ini 在哪；成品里负责释放内嵌的 DLL
tests/trainer_tests.cpp        配置读写的测试（控制台程序，临时目录）
cmake/embed.cmake              二进制文件 → C++ 数组（成品内嵌 DLL 用）
cmake/copy_if_missing.cmake    ini 只在输出目录里没有时才拷
```

- **加一项设置**：`settings.h` 的结构里加成员 + `settings.cpp` 的字段表里加一行（文件、键名、类型、范围）+ `pages.cpp` 里画出来；DLL 那边读同名的键。
- **验证命令**（都不碰游戏）：
  - `build\Release\trainer_tests.exe`：退出码 0 = 全过。
  - `gow4_trainer.exe --shot <png> <页 0-4> <样例 0-2>`：离屏画一帧（纯 CPU），页 4 是提示条。
  - `gow4_trainer.exe --check <txt>`：只读自检——读配置、找游戏、看 DLL 装没装、用真显卡设备建覆盖层画 5 帧；不注入、不写 ini、不显示窗口。
- **构建**：`.\build.ps1`（开发版，全部目标 → `build\Release`，会重新链接那里的 DLL）；`.\build.ps1 -Dist`（成品）。
  只想编修改器不动 DLL：`cmake --build build --config Release --target gow4_trainer trainer_tests`。
  DLL 改完先编到检查目录：`cmake --build build --config Release --target gow4_autoparry gow4_esp -- -p:OutDir=<仓库>\build\check\`。
  `build.ps1` 存成带 BOM 的 UTF-8：不带 BOM 时 Windows PowerShell 5.1 认不出 `-Dist` 参数，会悄悄跑成开发版。

### 容易漏的情况

| 情况 | 该有的表现 | 验证了吗 |
| --- | --- | --- |
| ini 不存在 / 只读 / 值写乱了 | 用默认值、越界的夹到范围内；写失败在菜单底部提示，不崩 | 测试覆盖 |
| 修改器新、DLL 旧（游戏里是 v6.23，没有 `master` 和重读事件） | 开关 1～2 秒后照常生效；总览页和 F12 提示条都说明总开关不起作用 | 只看过离屏图 |
| 游戏里的 DLL 是别处注入的 | 总览页提示设置对它不起作用，先卸载再注入 | 没验证 |
| 游戏没开 / 中途关了 / 重开（进程号变了） | 状态变「没在运行」，不崩；新进程满 15 秒后再自动注入一次 | 没验证 |
| 游戏刚启动、内存还读不到，或游戏是管理员身份开的 | 总览页显示「还读不到」，不说成「版本不对」 | 没验证 |
| 刚点了卸载马上点注入 | 3 秒内不注入同一个 DLL（它还在收尾） | 没验证 |
| 菜单里改键时按下的键 | 不当成快捷键触发；刚绑上的键要松开再按才算 | 没验证 |
| 菜单开着时切到别的程序 | 菜单自动收起，不盖在别的程序上 | 没验证 |
| 同时开了两个修改器 | 第二个直接退出并提示 | 没验证 |
| 自动注入时一个成功一个失败 | 提示条和总览页都留着失败的原因，不被后一个的成功清掉 | 没验证 |
